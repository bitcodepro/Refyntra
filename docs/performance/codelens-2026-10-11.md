# CodeLens cost while typing (2026-10-11)

What runs on the extension host for C# CodeLens, and what it costs. Same machine as the 2026-10-09 baseline.

## Per keystroke (document version)

VS Code asks `provideCodeLenses` again after typing pauses (it debounces by itself). Refyntra then only scans the
document text for type and member declarations (`scanCSharpDeclarations`, linear, no allocation per character beyond
`split`) and creates unresolved lenses. The scan result is cached per document version.

Measured with the bundled function (20 runs after 3 warm-up runs, synthetic C# with 3 declarations per 9 lines):

| Lines | Scan |
|---:|---:|
| 1,000 | 0.75 ms |
| 5,000 | 2.4 ms |
| 20,000 | 9.3 ms |

The e2e scenario `native-ui` also asserts that every scan of the Shop files stayed under 50 ms
(`RefyntraCodeLensProvider.scanTimes`), and the unit test asserts a 20,000-line scan under 250 ms on CI machines.

## Per visible lens (lazy)

`resolveCodeLens` runs only for lenses on screen. All lenses of one declaration share one `code/related` request per
document version (the engine also caches Related per workspace revision); a handler asks Related once more for its
request type ("sent from"). The request runs in the .NET host, off the extension host's thread, and is cancelled when VS
Code cancels the resolve (scrolling, typing). Warm `code/related` on the Shop fixture: see the 2026-10-09 baseline.

## Not done

No time budget is derived from these numbers. Large files with many declarations on screen issue one host request per
visible declaration after each typing pause; `refyntra.codeLens.enabled` turns the feature off.
