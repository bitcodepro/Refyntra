# OR1003 — 'async void' method

**Status: new (alpha).** Default severity `warning`. Quick fixes run through Refyntra's edit actions.

Reports an `async void` method or local function. Its caller cannot await it or observe its completion, and an
exception escaping it is rethrown on the synchronization context — usually crashing the process.

```csharp
public async void Refresh() { await LoadAsync(); }   // OR1003 → public async Task Refresh()
```

**Quick fix *Change 'async void' to 'async Task'*** — refused (`UsedAsDelegate`) when the method is used other than by
calling it (a method group assigned to `Action`, an event subscription), because a void-returning delegate requires
`void`. Callers in other files keep compiling (an unawaited call in an async method then gets the compiler's CS4014,
which makes the fire-and-forget visible).

### Not reported

- Event handlers: two parameters, the first `object`/`object?`, the second deriving from `EventArgs` (or named
  `…EventArgs`).
- Overrides and interface implementations (the signature is not the method's to choose), partial methods.
- `async` lambdas (commonly event handlers; their target type decides).

Fixture: `Cases/AsyncVoid.cs` (2 reported, 5 guards).

## Settings and suppression

- Setting `refyntra.rules.OR1003`: `off | hint | info | warning | error` (default `warning`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1003` … `#pragma warning restore OR1003` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1003…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
