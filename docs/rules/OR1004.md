# OR1004 — Discarded task (fire-and-forget)

**Status: new (alpha).** Default severity `warning`. Quick fixes run through Refyntra's edit actions.

Reports a call whose `Task`/`ValueTask` result is thrown away where the compiler does **not** warn: in methods that are
not async (the compiler's CS4014 only applies inside async methods) and conditional calls (`worker?.RunAsync();`).
The work may still be running when the method returns and its exceptions are lost.

```csharp
public void Save() { _repo.SaveAsync(); }          // OR1004 → _ = _repo.SaveAsync();  (or make Save async)
public async Task Run() { _worker?.RunAsync(); }   // OR1004 (CS4014 does not cover '?.')
```

**Quick fix *Discard the task explicitly ('_ = …')*** — documents the intent; it does not make the call safe. When the
right answer is to wait for it, make the method async (*Make method async*) and await it.

**On the compiler's CS4014** (an unawaited call in an async method) Refyntra adds *Add 'await'* and *Discard the task
explicitly*, with *… in document, project or solution* for *Add 'await'*. Refyntra does not report CS4014's cases itself.

### Not reported

- Deliberate starts of background work: `Task.Run`, `TaskFactory.StartNew`, `ContinueWith`.
- Results that are used: assigned (`_ = …`, `var t = …`), returned, awaited, passed on.
- Plain calls inside async methods (that is CS4014).

### Why not "missing ConfigureAwait(false)"

Deliberately not a rule: whether library code should use `ConfigureAwait(false)` is a project policy, not a defect, and
application code under ASP.NET Core has no synchronization context. See [overlap.md](overlap.md).

Fixture: `Cases/DiscardedTask.cs` (3 reported, 6 guards).

## Settings and suppression

- Setting `refyntra.rules.OR1004`: `off | hint | info | warning | error` (default `warning`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1004` … `#pragma warning restore OR1004` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1004…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
