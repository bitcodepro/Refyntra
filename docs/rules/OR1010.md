# OR1010 — 'string.Format' without arguments

**Status: new (alpha).** Default severity `info`. Quick fixes run through Refyntra's edit actions.

Reports `string.Format(format)` with a constant format and no arguments:

- when the format has no placeholder and only doubled braces, the call just returns the string with `{{`/`}}`
  un-doubled — the quick fix *Use the string directly* replaces it by the string (`"{x}"` for `"{{x}}"`, the constant
  itself for a named constant);
- when it has a placeholder or a single brace (`string.Format("{0}")`), it throws `FormatException` at run time — reported
  without a fix (an argument is missing).

```csharp
string.Format("hello")    // OR1010 → "hello"
string.Format("{0}")      // OR1010, no fix: throws FormatException
```

### Not reported

- Non-constant formats (`string.Format(userText)`: the result depends on the text), calls with arguments, the
  `IFormatProvider` overloads.

Fixture: `Cases/Format.cs` (4 reported, 3 guards).

## Settings and suppression

- Setting `refyntra.rules.OR1010`: `off | hint | info | warning | error` (default `info`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1010` … `#pragma warning restore OR1010` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1010…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
