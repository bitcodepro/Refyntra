# OR1002 — Sync over async

**Status: new (alpha).** Default severity `warning`. Quick fixes run through Refyntra's edit actions.

Reports a blocking wait on a task: `.Result` (Task&lt;T&gt;, ValueTask&lt;T&gt;), `.Wait()` without arguments (Task) and
`.GetAwaiter().GetResult()` (also after `ConfigureAwait(…)`). Blocking a thread on asynchronous work risks deadlocks
under a synchronization context and starves the thread pool under load.

```csharp
public async Task<int> TotalAsync()
{
    var t = LoadAsync();
    await Task.Yield();
    return t.Result;             // OR1002 → return await t;
}

public Task<int> Wrapped()
{
    var x = GetAsync().Result;   // OR1002 → var x = await GetAsync(); and the method becomes 'async'
    return Task.FromResult(x + 1);  //        (its returns are awaited: return await Task.FromResult(x + 1);)
}

public int Count() => CountAsync().GetAwaiter().GetResult();   // OR1002, no fix (see below)
```

**Quick fix *Use 'await'*** — offered when the code is in an async method, local function or lambda, or in a method
that already returns `Task`/`ValueTask` (it then gets `async`, keeping its signature; Make Async's rewrite awaits its
returns). The `await` is parenthesized where needed (`(await t).Length`).

**Reported without a fix** where `await` is impossible or would change a signature: methods returning `void` or a
value (making them async changes every caller — use *Make method async* deliberately), constructors, properties and
accessors, `lock` bodies, query expressions, `unsafe` code, catch filters. Field initializers are not reported.

### Not reported (false-positive guards)

- The task is known to be complete: it was awaited earlier in the method (`await t; … t.Result`), passed to an awaited
  or blocking `WhenAll` / `WhenAny` / `WaitAll` / `WaitAny`, or its `IsCompleted*` / `IsFaulted` / `IsCanceled` /
  `Status` is checked in the method.
- `Task.FromResult(…)`, `Task.FromException`, `Task.FromCanceled`, `Task.CompletedTask`.
- A lambda parameter (`ContinueWith(t => t.Result)`: the antecedent of a continuation is complete).
- `Wait(timeout)` / `Wait(token)` (an explicit bounded wait), and any `Result` that is not Task's (a DTO property).

Fixture: `tests/fixtures/Inspections/Inspections.App/Cases/SyncOverAsync.cs` (7 reported cases, 8 guards). On this
repository's own sources (107 files) it reports 9 `GetAwaiter().GetResult()` calls, all real blocking waits in
synchronous code paths (no fix offered there).

## Settings and suppression

- Setting `refyntra.rules.OR1002`: `off | hint | info | warning | error` (default `warning`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1002` … `#pragma warning restore OR1002` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1002…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
