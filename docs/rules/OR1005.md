# OR1005 — Disposable local never disposed

**Status: new (alpha).** Default severity `info`. Quick fixes run through Refyntra's edit actions.

Reports a local variable that holds a disposable object **created in the method** (`new …` or `File.Open`,
`OpenRead`, `OpenWrite`, `OpenText`, `Create`, `CreateText`, `AppendText`) when no use of it can hand the object over:
every use is a member call or read whose result is `void`, a number, `bool`, `char`, `string`, an enum or `DateTime`
(also awaited), and it is never disposed.

```csharp
public string Read(string path)
{
    var reader = new StreamReader(path);   // OR1005 → using var reader = new StreamReader(path);
    return reader.ReadToEnd();
}
```

**Quick fix *Dispose with a 'using' declaration*** (C# 8 or later; reported without a fix on older language
versions). The object is then disposed at the end of the enclosing block.

### Not reported (ownership is conservative)

- The variable is returned, assigned anywhere, passed as an argument, stored in a field/collection, captured by a lambda
  or local function, or used through a member whose result is an object (`writer.BaseStream`, `cts.Token`) — the object
  or something tied to its lifetime may live on.
- `Dispose()`, `DisposeAsync()` or `Close()` is called, or it is already in `using`.
- Types whose disposal is not needed or changes behaviour: `Task`, `MemoryStream`, `StringReader`, `StringWriter`,
  `DataTable`, `DataSet`, `System.Threading.Timer`, `System.Timers.Timer` (a timer disposed at the end of the block
  would stop firing), ref structs.
- Factory calls other than the `File` ones above (ownership of a returned object is unknown), declarations with several
  variables, declarations outside a block (e.g. a switch section).
- Unused variables.

Fixture: `Cases/Undisposed.cs` (3 reported, 11 guards).

## Settings and suppression

- Setting `refyntra.rules.OR1005`: `off | hint | info | warning | error` (default `info`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1005` … `#pragma warning restore OR1005` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1005…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
