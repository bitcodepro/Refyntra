# OR1007 — String concatenation in a loop

**Status: new (alpha).** Default severity `info`. Quick fixes run through Refyntra's edit actions.

Reports `s += x` on a local `string` declared outside a loop and only appended to inside it: every iteration copies the
whole string (quadratic time, one garbage string per iteration). Reported once per variable and loop, at its first
`+=`.

```csharp
var s = "";
foreach (var p in parts)
{
    s += p;          // OR1007 → var sBuilder = new StringBuilder(); … sBuilder.Append(p); …
    s += ",";
}
return s;            //          var s = sBuilder.ToString(); after the loop
```

**Quick fix *Use a StringBuilder*** — the declaration becomes `var <name>Builder = new StringBuilder(<initializer>)`
(no argument for `""`/`string.Empty`), each `+=` an `Append`, and when the string is used after the loop it is
declared again right after it with `ToString()`. Adds `using System.Text;` when needed. Refused when the variable is
used between its declaration and the loop, captured by a lambda, declared together with other variables or not in the
loop's block.

### Not reported

- The loop also reads the string (`while (!names.Add(n)) n += "1";`, `if (s.Length > 100) break;`): it needs the string
  on every iteration, so a StringBuilder would not help.
- Fields and properties, locals declared inside the loop, numbers (`sum += i`), a single `+=` outside loops.

Fixture: `Cases/ConcatInLoop.cs` (2 reported, 6 guards). On this repository's sources the rule found 3 candidates, all
of them loops that read the string; that is why such loops are excluded.

## Settings and suppression

- Setting `refyntra.rules.OR1007`: `off | hint | info | warning | error` (default `info`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1007` … `#pragma warning restore OR1007` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1007…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
