# OR1006 — Possible multiple enumeration

**Status: new (alpha).** Default severity `info`. Quick fixes run through Refyntra's edit actions.

Reports the second enumeration of an `IEnumerable<T>` parameter, or of a local declared `IEnumerable<T>` whose
initializer is a lazy sequence, on the same path of a method. Enumerations are `foreach` and the LINQ operators that
run immediately (`Any`, `Count`, `First`, `Sum`, `ToList`, …). Each enumeration re-runs a query, re-reads a stream or
hits a database again. The first enumeration is a related location.

```csharp
public int Total(IEnumerable<int> items)
{
    if (!items.Any()) return 0;
    return items.Sum();            // OR1006 → var itemsList = items.ToList(); at the start, uses replaced
}

IEnumerable<int> q = source.Where(x => x > 1);   // OR1006 at the second use → source.Where(x => x > 1).ToList()
```

**Quick fix *Materialize once with 'ToList()'*** — a local: its initializer gets `.ToList()`; a parameter: a new local
`<name>List` is declared first in the body and every use is replaced (`nameof(…)` stays). Adds `using System.Linq;`
when needed. Not offered for expression-bodied members.

### Not reported

- Enumerations in mutually exclusive branches (`if`/`else`, `?:`, switch sections or arms), or after a branch that
  returns or throws.
- A variable that is reassigned (`items = items.ToArray();`), a `ref`/`out`/`in` parameter.
- A use inside a lambda or local function (it may run any number of times; nothing is reported for that variable).
- Collections: a declared type other than `IEnumerable<T>` (`List<T>`, arrays, `IReadOnlyCollection<T>`, …) or a local
  whose initializer is a collection (`IEnumerable<int> xs = new List<int>()`, `….ToList()`).
- Deferred operators (`Where`, `Select`) — they do not enumerate.

Fixture: `Cases/MultipleEnumeration.cs` (3 reported, 10 guards).

## Settings and suppression

- Setting `refyntra.rules.OR1006`: `off | hint | info | warning | error` (default `info`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1006` … `#pragma warning restore OR1006` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1006…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
