# OR1008 — 'Where(…)' before an operator that takes a predicate

**Status: new (alpha).** Default severity `hint`. Quick fixes run through Refyntra's edit actions.

Reports `Where(p).First()`, `FirstOrDefault`, `Last`, `LastOrDefault`, `Single`, `SingleOrDefault`, `Any`, `Count` and
`LongCount` (System.Linq.Enumerable): the operator's predicate overload does the same in one call without the
intermediate iterator.

```csharp
xs.Where(x => x > 1).First()     // OR1008 → xs.First(x => x > 1)
```

**Quick fix *Pass the predicate to the operator*** (line breaks of a fluent chain are kept).

### Not reported

- The indexed overload `Where((x, i) => …)` (no predicate overload takes an index).
- `IQueryable` (Queryable's operators: the provider translates both forms, and Refyntra does not change queries).
- Anything between `Where` and the operator (`Where(…).Select(…).First()`).

Fixture: `Cases/Linq.cs` (3 reported, 3 guards).

## Settings and suppression

- Setting `refyntra.rules.OR1008`: `off | hint | info | warning | error` (default `hint`). `hint` shows dots under
  the code and no Problems entry.
- Reported for the C# files open in the editor (the client sends their URIs with `analysis/run`, protocol 1.16); each
  document is analysed on its own and its result is reused until its text or a signature of its project changes.
- Suppress like a compiler warning: `#pragma warning disable OR1008` … `#pragma warning restore OR1008` (a bare
  `#pragma warning disable` too), or `[SuppressMessage("<category>", "OR1008…")]` on the member, type or assembly
  (`Target = "~M:…"` / `Scope = "namespaceanddescendants"` are honoured). Generated code is never analysed.
- Quick fixes are Refyntra edit actions: computed by the host, applied only when the document has no new compiler error,
  one undo step. *… in document, project or solution* applies the same fix at every result of the scope as one
  previewed plan (Fix in scope, `csharp.fixAll`); results whose fix would add a compiler error are skipped and counted.
