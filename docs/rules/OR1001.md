# OR1001 — scoped service captured by a singleton

**Status: experimental.** Default severity `warning`; setting `refyntra.rules.OR1001` = `off | information | warning`.
No code fix: changing a lifetime is an architectural decision with behavioural consequences.
Overlap with existing tools: [overlap.md](overlap.md).

## What it reports

A warning only for a **proven path inside one composition root**:

```
singleton registration
  → the single public constructor of its implementation type
    → a parameter whose service type is registered in the same root
      → that registration (transient: continue with its implementation's constructor) …
        → a scoped registration
```

The warning is placed on the singleton registration. Its related information is the whole path, in order: the
singleton registration, each constructor parameter, each intermediate registration and the scoped registration, each
with its location. Example (from the corpus):

```
Singleton 'ReportScheduler' captures scoped 'IUnitOfWork' via ReportScheduler(IReportBuilder builder)
→ ReportBuilder(IUnitOfWork uow) in DiRules.App.Cases.TransitiveCase.AddTransitiveCase (DiRules.App).
  1. Singleton registration AddSingleton<ReportScheduler>()                 Transitive.cs:24
  2. Constructor parameter 'builder' of ReportScheduler(IReportBuilder builder, ILogger<ReportScheduler> logger)  Transitive.cs:15
  3. Transient registration AddTransient<IReportBuilder, ReportBuilder>()   Transitive.cs:23
  4. Constructor parameter 'uow' of ReportBuilder(IUnitOfWork uow)          Transitive.cs:10
  5. Scoped registration AddScoped<IUnitOfWork, UnitOfWork>()               Transitive.cs:22
```

Definitions:

- **Composition root**: the method that contains the registration call (top-level statements are
  `Program.<Main>$ (<project>)`), as in Related (`src/dotnet/CONTRACT-NOTES.md` §12).
- **Registrations**: `AddSingleton/AddScoped/AddTransient` and `TryAdd*` in generic and `typeof` forms from
  `Microsoft.Extensions.DependencyInjection.Abstractions` (identity: method + containing type + assembly). A path may end
  at a framework registration with a documented scoped lifetime (e.g. `AddDbContext<T>()`), whose constructor is not
  needed. `AddHostedService<T>()` is a singleton start (DI constructs `T`).
- **Keyed, factory, instance and open generic registrations** are shown in Related (keyed with their key, factories as
  *likely* with the delegate location, open generics with their closed usages as *likely*), but OR1001 behaves as
  before: keyed registrations (`AddKeyed*`, `TryAddKeyed*`) are ignored entirely (they never satisfy a non-keyed
  parameter; a `[FromKeyedServices]` parameter abstains with `KeyedService`; a keyed singleton is not a start), and
  factory, instance and open generic registrations still abstain. No new proof is claimed, so the corpus numbers
  (`tests/fixtures/DiRules/expected-OR1001.json`: 3 warnings) are unchanged.
- **Service identity**: full metadata name, type arguments and declaring assembly — a same-name type from another
  namespace or assembly is a different service.
- **A singleton that is reached in the middle of a path** stops that path: it gets its own warning.

## When it stays silent (abstentions)

Anything it cannot prove is an *abstention*: no Problems entry, but an explanation reachable through the code action
**"Refyntra: why OR1001 did not check this registration"** on the registration line (warnings have
**"Refyntra: explain OR1001 (proof path)"**). `analysis/run` returns abstentions as `{ ruleId, reason, message, location }`.

| Reason | Meaning |
|---|---|
| `ConditionalRegistration` | A registration on the path (or the singleton itself) is inside `if`/`switch`/`?:`/`?.`/`&&`/`||`/`??`, a loop, `try`/`catch`, a lambda or a local function, or follows an earlier `return`/`throw`/`goto` in the method. |
| `FactoryRegistration` / `InstanceRegistration` | The singleton or a dependency is registered with a factory delegate or an instance. |
| `OpenGeneric` | The dependency is provided by an open generic registration, or the singleton is one. |
| `KeyedService` | A constructor parameter has `[FromKeyedServices]`. Keyed registrations are not followed. |
| `EnumerableService` | A parameter is `IEnumerable<T>` (not followed in this version, even if every registration is known). |
| `TryAdd` | A registration on the path is `TryAdd*`: an earlier registration made elsewhere may win. |
| `MultipleRegistrations` | The dependency is registered more than once in the root with different lifetimes or implementations. Identical duplicates are accepted. |
| `MayBeOverridden` | A connected root (linked by calls that pass the service collection) registers the dependency differently; the last registration wins at run time. |
| `RegisteredInAnotherRoot` | The dependency is registered only in another composition root (OR1001 proves paths inside one root). |
| `UnregisteredService` / `FrameworkService` | No registration of the dependency in source (missing, or a framework/library service whose lifetime is not modelled). A parameter with a default value is skipped instead. |
| `MultipleConstructors` / `NoPublicConstructor` / `NotConstructible` / `UnresolvedType` | Constructor selection is not modelled; abstract/interface/error types. |
| `FrameworkRegistration` / `UnknownLifetime` | A transient framework registration (e.g. a typed `HttpClient`) or a non-constant lifetime argument on the path. |
| `UnresolvedRegistrationCall` | A root of the component passes the service collection to a method whose target is not resolvable (delegate, virtual/interface method). |
| `PartialLoad` | The root's project or one of its project references is not completely loaded. |
| `DepthLimit` | The path is longer than 12 constructor edges. |

Only the first blocking reason is the `reason`; the message lists how many more there were.

## Incremental invalidation

The unit of analysis is a **connected component** of composition roots: roots linked by a call that passes the service
collection (`services.AddInfrastructure()`), in either direction. A component's result is reused on a new snapshot only if
all of its dependencies are unchanged:

- the documents containing its registrations and service-collection calls (the composition roots),
- the documents declaring every type the proof looked at (implementation types and their constructors, service types),
- the document sets and load states of the involved projects,
- the membership of the component.

So an edit to a constructor in another file recomputes the component (test
`DiRulesIncrementalTests.EditingAConstructorFileRecomputesTheRootAndAnUnrelatedEditReusesIt`, e2e scenario `di-rules`),
and an edit to an unrelated file reuses the previous result. The registration facts themselves are recomputed per
snapshot (cached per immutable solution and shared with Related). In the extension, `analysis/run` runs 700 ms after the
last edit; the collection is cleared when the backend session (epoch) changes.

## Quality corpus

Corpus: `tests/fixtures/DiRules` (copy-based tests), labels in `tests/fixtures/DiRules/expected-OR1001.json`.
Ground truth was **verified** with Microsoft.Extensions.DependencyInjection 10.0 itself: each case registered into a
`ServiceCollection` built with `ValidateOnBuild = true, ValidateScopes = true` (see [overlap.md](overlap.md)). The
expected result of every case is asserted by `DiRulesTests.CorpusMatchesTheManualLabels`.

20 singleton registrations, 12 of which capture a scoped service at run time.

| Case | Truth | OR1001 | Class |
|---|---|---|---|
| direct (`Program.cs`) | capture | warning | TP |
| transitive (singleton → transient → scoped) | capture | warning | TP |
| `typeof` forms | capture | warning | TP |
| different roots (both called from `Program`) | capture | abstain `RegisteredInAnotherRoot` | FN (out of scope) |
| conditional (`if`) | capture when the branch runs | abstain `ConditionalRegistration` | FN (out of scope) |
| factory-registered scoped dependency | capture | abstain `FactoryRegistration` | FN (out of scope) |
| factory-registered singleton | capture (detected only at resolve time by DI) | abstain `FactoryRegistration` | FN (out of scope) |
| `IEnumerable<T>` | capture | abstain `EnumerableService` | FN (out of scope) |
| `TryAdd` | capture | abstain `TryAdd` | FN (out of scope) |
| open generic | capture | abstain `OpenGeneric` | FN (out of scope) |
| keyed | capture | abstain `KeyedService` | FN (out of scope) |
| two public constructors | capture | abstain `MultipleConstructors` | FN (out of scope) |
| same-name foreign type | none (activation fails: unresolved service) | abstain `UnregisteredService` | TN |
| overridden by a later call (last registration is a singleton) | none | abstain `MayBeOverridden` | TN |
| duplicate registrations (last is a singleton) | none | abstain `MultipleRegistrations` | TN |
| clean: singleton → singleton | none | — | TN |
| clean: singleton → transient | none | — | TN |
| clean: singleton without dependencies (×3) | none | — | TN |

| Measure | Value |
|---|---|
| TP / FP / FN / TN | 3 / 0 / 9 / 8 |
| Precision | 3/3 = 100 % (95 % Wilson interval 44 %–100 %) |
| Recall over all captures | 3/12 = 25 % |
| Recall in the supported scope (unconditional constructor paths in one root) | 3/3 |
| Abstentions | 12 of 20 singleton registrations (60 %): FactoryRegistration 2, and 1 each of ConditionalRegistration, EnumerableService, TryAdd, OpenGeneric, KeyedService, MultipleConstructors, MultipleRegistrations, MayBeOverridden, RegisteredInAnotherRoot, UnregisteredService |
| Known false proven warnings | none |

**Honest reading.** The corpus is tiny, synthetic and written together with the rule, so it is a regression suite, not
a quality measurement; the precision interval is wide and recall is low by design (every FN is an abstention, never a
wrong statement). The rule stays **experimental**; see the real-code holdout below.

## Public regression project

The pinned public regression solution (`tests/regression/manifest.json`, jasontaylordev/CleanArchitecture v8.0.0, MIT, MediatR 12.1.1; 9 projects) has one singleton start; OR1001 reports no warning and abstains on it (`InstanceRegistration`). `pnpm test:regression` keeps this result fixed.

OR1001 stays **experimental**: the corpora used so far contain no true scoped-into-singleton capture outside the synthetic corpus above, so precision and recall on real code are not yet measured, and factory registrations (which make the rule abstain) are common in real composition roots.

## Not covered (by design in this version)

- Paths across composition roots, through factories, `IEnumerable<T>`, keyed services, open generics, `TryAdd`,
  conditional registrations, several constructors (`ActivatorUtilitiesConstructor` included), property injection,
  `IServiceProvider.GetService` inside a constructor, and registrations made inside libraries (assembly scanning such as
  `AddMediatR`/Scrutor is not seen; a library extension method is assumed not to re-register source services).
- Callers outside the solution: a public extension method may be called by code Refyntra does not load.
- `new SomeType(services)`: the service collection passed to a constructor is not tracked.
