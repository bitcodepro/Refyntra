# Alpha capabilities

Planned alpha scope. None of it is claimed as verified on a release build yet.

Guarantee levels:

- **owned-semantic**: resolved by Roslyn from symbol identity.
- **delegated**: answered by another semantic engine: VS Code's built-in TypeScript/JavaScript features (public provider
  commands), or a language server Refyntra bundles and runs itself (Pyright for Python, rust-analyzer for Rust). Refyntra
  does not compute these results semantically; for its own servers it owns the process and the document view, so
  results and plans are bound to the document versions the server saw (ADR-002 amendment).
- **heuristic**: derived from recognized code patterns; shown with evidence and limits.

Every relation also carries a **confidence**: `proven` (matched by verified symbol identity of a known framework
version) or `likely` (framework extension methods whose registration happens inside the framework, MediatR versions
outside the verified range). The capability ids are `csharp.find`, `csharp.related`, `csharp.rename` and
`csharp.references` (protocol-v1.md "Capability ids"); framework support is part of `csharp.related`.

| Capability | Guarantee | Limitations |
|---|---|---|
| Find symbol (`type:`, `member:`, `project:` filters) | owned-semantic | Loaded projects only; metadata-only symbols may be missing; project context shown when ambiguous. An empty query lists the solution's types (sorted, limited) |
| Find EF Core entities (`entity:`, `table:NAME`) | owned-semantic | `entity:` lists the types mapped by a source DbContext (name filter like `type:`); `table:` matches the mapped table name (explicit `ToTable`/`[Table]`, `schema.name` too, or the convention name). Combines with `project:`; not with `member:`/`route:`/`method:` |
| Related: declarations, usages, implementations | owned-semantic | Scope is the loaded solution and chosen project context |
| MediatR request to handlers, and `Send` call sites | owned-semantic (part of Related); confidence proven for MediatR 10–12 / Contracts 1–2, likely otherwise | Matched by verified symbol identity of the MediatR interfaces. Statically visible generic forms only; dynamic dispatch and runtime registration are reported as unknown |
| Minimal API endpoints (`MapGet`, `MapPost`, etc.) | owned-semantic (part of Related); confidence proven | Matched by the verified ASP.NET Core `Map*` methods. Simple, statically visible routes; computed routes and dynamic grouping are marked dynamic (known prefix only) |
| MediatR pipeline behaviors, streams, notification contravariance | owned-semantic (part of Related, group `handlers`, kind `mediatr.behavior`) | `IPipelineBehavior<TRequest,TResponse>` / `IStreamPipelineBehavior<,>` implementations: a closed behavior relates to its request with the version confidence; an open generic one is labelled "applies to every request (open generic)", confidence likely, shown only when its `TRequest` constraints (class/struct, constraint types; a constraint mentioning `TResponse` such as `IRequest<TResponse>` only by generic definition) are satisfied. Neither registration nor pipeline order is claimed. `IStreamRequest<T>` → `IStreamRequestHandler<,>` (proven) and `CreateStream` call sites. A handler of a base notification (base class or interface) relates to a derived notification as likely (contravariance; whether the container dispatches variantly is not proven). Generic notification handlers (`INotificationHandler<T>` with `T` a type parameter) are not related |
| MVC controllers and actions | owned-semantic (part of Related and Find, endpoint kind `mvc`); confidence proven, naming heuristic as heuristic | Controllers: public, non-abstract, non-generic classes deriving from `Microsoft.AspNetCore.Mvc.ControllerBase` or carrying `[Controller]`/`[ApiController]` (identity: metadata name + assembly `Microsoft.AspNetCore.Mvc.Core`), not `[NonController]`; the `XController` naming convention only when a base type does not resolve (heuristic). Actions: public instance non-generic methods of the controller and its source base classes, without `[NonAction]` (also inherited through overrides), excluding `Dispose()` of an `IDisposable` controller. Routes: `[Route]` on the controller (all levels of the class chain) × templates of `[HttpGet/Post/Put/Delete/Patch/Head/Options("t")]`, `[Route("t")]` (verbs from template-less verb attributes) and `[AcceptVerbs(..., Route = "t")]`; `/` and `~/` templates override the controller route; several attributes give several endpoints; tokens `[controller]` (name without `Controller`), `[action]` (`[ActionName]` or the method name without `Async`), `[area]` (`[Area]`), `[[`/`]]` escapes; constraints such as `{id:int}` kept as text. Unknown tokens and an `[area]` without `[Area]` stay in the route, marked dynamic. `[ApiExplorerSettings(IgnoreApi = true)]` actions are still endpoints (noted). Actions without any attribute route, and `MapControllerRoute`/`MapAreaControllerRoute`/`MapDefaultControllerRoute` patterns, are endpoints marked dynamic with "conventional route, not resolved" — patterns are never matched to actions. Related: action ↔ its endpoints, controller → all its endpoints, a MediatR `Send` inside an action → that endpoint. Composition root: `MVC controllers (<project>)`, per project. Not modelled: custom `IRouteTemplateProvider`/`HttpMethodAttribute` subclasses (shown without verbs), `[Host]`, route `Order`/`Name`, application model conventions, `RoutePrefix` conventions, `SuppressAsyncSuffixInActionNames = false`, Razor Pages |
| Frontend ↔ backend HTTP links (TS/JS client call ↔ ASP.NET endpoint) | heuristic (part of Related: endpoint and handler from a call, group `clients` from an action/handler/controller; Find `client:`); provenance `http.links` | Literal URLs only: string and template literals (`${…}` = route parameter), `+` concatenation with variables, same-file consts and `axios.create({ baseURL })`; `fetch`, `axios`, Angular `HttpClient`, AngularJS `$http`, `ky`, `superagent`. Matching normalises slashes and literal case, route parameters and simple constraints, the HTTP method when known; ASP.NET-like precedence; ties are shown as ambiguous; dynamic routes are not matched; absolute URLs only for `refyntra.http.origins`; base paths only from `refyntra.http.basePaths`. Bounded workspace scan (excludes, 5000 files, 512 KB). Not modelled: runtime/configured base URLs, other-file helpers, proxies, rewrites, gateways, generated clients |
| HTML/CSS/SCSS/LESS ↔ code links | proven for CSS Modules (static `styles.foo`/`styles['foo']` of an import resolved to the `.module.css`/`.scss`/`.less` file), SCSS/LESS variables and SCSS mixins through resolved `@use`/`@forward`/`@import` (likely when several definitions are visible), and resolved stylesheet imports/links; heuristic for global classes and ids (groups `styles`, `usedBy`, `unused`; Find `css:`); route `web.styles` | Parsed in-process by the bundled `vscode-css-languageservice`/`vscode-html-languageservice` (MIT; no server, no other extension). Global classes: linked stylesheets first (`<link>`, `<style>`, `import './x.css'`, Angular `styleUrl(s)`), else every global stylesheet, "ambiguous" across files. Dynamic class names (template literals, `styles[name]`, `{{ }}`) are unknown. "Possibly unused" selectors are information only. Rename of CSS classes is unavailable (class names in strings cannot be proven; CSS Module rename would need cross-language edits). Bounded scan (excludes, 5000 files, 512 KB). Not modelled: `.sass`, Vue/Svelte SFCs, CSS-in-JS, `:global`, `@extend`, LESS mixins, package/alias imports |
| React / Next.js / Angular (web worker, ADR-007) | proven: React JSX tag → component, attribute → props member, props member → attributes, custom hook ↔ calls (TypeScript checker); Angular template element/binding → component/input/output, component → template, selector usages, input/output template uses, `providers`/`viewProviders`, `providedIn`, constructor/`inject()` injection, NgModule `declarations`/`imports`/`exports` (Angular language service + checker). likely: React context providers/consumers, Next.js routes (app/pages router conventions, endpoints with route templates), Angular route definitions. heuristic: `<Link href>`/`router.push`/`redirect`/`fetch('/api/…')` literals ↔ Next.js routes. Find `component:`, `page:`; provenance `web.frameworks` | Refyntra's own worker process with the bundled TypeScript 6.0.3 and Angular language service 22.2.1 (no other extension, no project code, trusted workspaces only, lazy start, 3 GB heap cap, restart policy). Angular 17–22 (22 verified), other majors refused with a reason. Next.js: route groups, dynamic `[id]`/`[...slug]`/`[[...slug]]`, parallel `@slot`, intercepting `(.)`, private `_folders`, route handlers with exported methods, pages router + `pages/api`, `'use client'`/`'use server'` boundaries; middleware, rewrites, redirects, basePath, i18n are limitations — never a full routing graph. Missing/unused props are information on the relation, never diagnostics. Angular stylesheets are linked by the HTML/CSS route. Not modelled: Vue/Svelte, React Native, Angular signal queries, loadChildren prefixes from other files |
| Explicit DI registrations (interface to implementation) | owned-semantic (part of Related); confidence proven, framework extensions likely | Explicit `AddScoped`/`AddTransient`/`AddSingleton`/`TryAdd*` forms (proven). Framework extensions `AddDbContext`/`AddDbContextPool`/`AddDbContextFactory` (EF Core), `AddHostedService`, typed `AddHttpClient`, `AddOptions<T>` are *likely*, matched by method, containing type and assembly; lifetime from a constant `contextLifetime`/`lifetime` argument or the documented default. Assembly scanning and conditional or reflective registration are not resolved. Keyed: `AddKeyedSingleton/Scoped/Transient` and `TryAddKeyed*` with the key (`registration.key`: the constant value, or the expression as written with a limitation); a `[FromKeyedServices(key)]` parameter relates to the keyed registrations of its type with the same key. Factory registrations: `implementationKind: 'factory'`, `factoryLocation` = the delegate, confidence likely. Instance registrations: `implementationKind: 'instance'`, the implementation is the instance's static type. Open generic `typeof(IRepo<>), typeof(Repo<>)`: the registration itself, plus constructor parameters of source classes that take a closed construction (`IRepo<Widget>`) as `di.openGenericUsage`, confidence likely (a closed registration or another composition root may win; constraints not checked) |
| EF Core model navigation | owned-semantic (part of Related, group `data`, kinds `efcore.*`); confidence proven, conventions and assembly scans likely, dynamic model building heuristic ("unknown") | Identity: `DbContext`, `DbSet<T>`, `IEntityTypeConfiguration<T>`, `ModelBuilder`, `EntityTypeBuilder<T>` (assembly `Microsoft.EntityFrameworkCore`), `Migration`/`MigrationBuilder` (`.Relational`), `ModelSnapshot`, `[DbContext]`; fluent methods only when declared in a `Microsoft.EntityFrameworkCore*` assembly; `[Table]`/`[Key]`/`[ForeignKey]`/`[NotMapped]` from `System.ComponentModel.Annotations`. A same-name DbContext/DbSet never matches. Entities: `DbSet<T>` properties (also of source base contexts), `Entity<T>()`/`Entity(typeof(T))` in `OnModelCreating`, `ApplyConfiguration(new X())` (proven), `ApplyConfigurationsFromAssembly(typeof(X).Assembly)` → the source configurations of that assembly (likely), types reachable through navigation properties that have a key (`Id`, `<Type>Id`, `[Key]`) (likely). Tables: constant `ToTable(name[, schema])` and `[Table(Name, Schema)]` (proven); otherwise the `DbSet` property name or the type name, "convention" (likely); naming-convention plugins and `ToView`/TPH/TPT/TPC table sharing are not modelled. Navigations: fluent `HasOne/HasMany` (+ `WithOne/WithMany`, `HasForeignKey` lambdas or strings) and `OwnsOne/OwnsMany` (proven), `[ForeignKey]` (proven), other reference/collection properties to entities (likely); `[NotMapped]` excluded; many-to-many skip navigations and shadow navigations are not modelled. Queries: every use of a `DbSet<T>` property or `Set<T>()` outside a DbSet definition, grouped per method (per lambda in top-level statements), linked to the enclosing Minimal API/MVC endpoint; the SQL is not derived. Migrations: `[DbContext(typeof(C))]` links context → migration/snapshot (proven); `MigrationBuilder` table arguments (`name:` of Create/Drop/RenameTable, `table:`, `principalTable:`) and snapshot `Entity("Full.Name")` link an entity (likely); read-only. DbContext → `AddDbContext*` registrations come from the DI module. Unknown: `Entity(...)`/`ApplyConfiguration(...)` in loops or with runtime types, reflection (`GetTypes`, `CreateInstance`, `MakeGeneric*`) in `OnModelCreating`, an assembly expression other than `typeof(X).Assembly`. Never: runtime model building, design-time services, database access |

| Rename | owned-semantic | Preview, then apply (`refyntra.rename.apply`, on by default; off = preview-only): mandatory revalidation of the full read set after confirmation (a `limited` plan stays limited and needs a second confirmation listing its limitations), synchronous hash check of every target, text-only `applyEdit`, per-file post-state reconciliation, no save, no automatic rollback, Undo through the editor. No moves; the only file operation is File rename: renaming the file together with a top-level type (`Foo.cs`, partial `Foo.*.cs`), offered on by default only when the guards and the static Compile-membership proof hold (otherwise text-only with the reason), applied after the text edits as a separate `renameFile` (never overwriting), reconciled, host resynced by `workspace/didRenameFiles`; if it fails the text edits stay applied and this is reported (Undo offered, no rollback); generated, read-only, non-UTF-8, mixed-line-ending (closed file), metadata, linked-mismatch, incomplete-closure and new-compiler-error renames are refused. | TS/JS Find (`typescript.find`) | delegated | Workspace symbols of the installed TypeScript/JavaScript provider (`vscode.executeWorkspaceSymbolProvider`), TS/JS files only, merged with C# results (route label per item, exact-location dedupe). Completeness unknown; never a complete index. `type:`/`member:` filter by the provider's symbol kind; `project:`, `route:`, `method:` give no TS/JS results |
| TS/JS Related (`typescript.related`, `typescript.references`) | delegated | Declarations (`vscode.executeDefinitionProvider`) and references (`vscode.executeReferenceProvider`); confidence likely, completeness unknown. No framework relations (`typescript.frameworkRelations` is unavailable: no TS/JS framework module) |
| Move Type to File (`csharp.moveTypeToFile`) | owned-semantic | Actions on the declaration of a top-level type in a file with other top-level types (nested types and single-type files: not offered). New `<Type>.cs` in the same folder: same namespace declarations (file-scoped/block), banner, attached comments, attributes, only the usings the moved code needs; every name must bind to the same symbol as before. | Generate handler (`csharp.generateHandler`) | owned-semantic | Actions on a MediatR request (`IRequest<T>`/`IRequest`, verified identity, MediatR 10–12) without a source handler. `<Request>Handler.cs` implementing `IRequestHandler<,>`/`IRequestHandler<>`, `Handle` throws `NotImplementedException`; folder: most handlers first (QuickPick of handler folders and the request folder), namespace from `RootNamespace` + folders, file-scoped when the project uses it, minimal usings. | Code Cleanup (`csharp.cleanup`) | owned-semantic | Command `refyntra.cleanup` on a file, folder, project or the workspace (max 2000 C# files); fixes from `refyntra.cleanup.profile`, toggled per run: `removeUnnecessaryUsings` (compiler CS8019 in every context; global usings kept), `sortUsings` (order only; `dotnet_sort_system_directives_first`), `fileScopedNamespace` (only with `csharp_style_namespace_declarations = file_scoped`, C# ≥ 10, one namespace), `whitespace` (only `trim_trailing_whitespace` / `insert_final_newline` from `.editorconfig`). A change is kept only when the semantic fingerprint (bindings, types, declared symbols, literal values, diagnostics, doc comments bound) is unchanged in every project context; idempotent. One text-only plan through the rename pipeline (revalidation, single EditApplier, reconcile, not saved, Undo). Skipped with reason: `GeneratedCode`, `ReadOnlyFile`, `UnsupportedEncoding`, `MixedLineEndings`, `FileTooLarge`, `IncompleteProject`, `ConditionalCompilation` (usings/namespaces of `#if` files), `LanguageVersion`, `NotSingleNamespace`, `NamespaceLayout`, `MultiLineString`, `UnsortableUsings`, `SemanticsNotProven`. Not offered: IDE code-style fixes (`editorConfigCodeStyle`, internal Roslyn APIs only) |
| TS/JS Rename (`typescript.rename`) | delegated, state limited | Provider-managed semantic coverage: fingerprints of every affected document, `vscode.prepareRename` + `vscode.executeDocumentRenameProvider`, refusal of resource/snippet/end-of-line/non-file edits, the same preview, then before apply the provider is asked again and the edit must be identical and every fingerprint unchanged; applied by the same EditApplier. Never `valid`; compilation delta `not-run`; always needs the limited confirmation. When safety cannot be confirmed the editor's own Rename is offered, labelled as not validated by Refyntra |
| Python / Rust Find (`python.find`, `rust.find`) | delegated (Refyntra-run server) | `workspace/symbol` of the language server Refyntra bundles and runs itself: Pyright 1.1.414 (route `python.pyright`) or rust-analyzer 2026-09-21 (route `rust.rust-analyzer`); no other extension is used. `.py`/`.pyi` and `.rs` files only; route labels `Python (delegated)` / `Rust (delegated)`. Completeness unknown; never a complete index. The server starts on the first document of its language in a trusted workspace; before that Find notes `NotStarted` |
| Python / Rust Related (`python.related`, `rust.related`, `*.references`) | delegated (Refyntra-run server) | `textDocument/definition`, `textDocument/references` (with declaration) and `textDocument/implementation` (when offered) of the bundled server; confidence likely, completeness unknown; results computed while a document changed (new server version) are dropped and asked again. `python.frameworkRelations` / `rust.frameworkRelations` unavailable (`NoFrameworkModule`) |
| Python / Rust Rename (`python.rename`, `rust.rename`) | delegated (Refyntra-run server), state limited | `textDocument/prepareRename` + `textDocument/rename` on the documents Refyntra itself synchronised (didOpen/didChange/didClose with recorded versions). The plan records the server, its version and the document versions the edit was computed on (`serverSession`); a `TextDocumentEdit` for another version → `DocumentChanged`; a closed-file edit that does not replace the old name in the file read from disk → `ServerViewMismatch`; resource operations (create/rename/delete file) → `ResourceOperation` (refused in this version); snippet/annotated-only/non-file edits refused. Before apply the same session is asked again: identical edits, identical fingerprints and identical document versions, else stale. Never `valid`; compilation delta `not-run`. Name checks before the server is asked: `InvalidName` (Python: Unicode identifier, no hard keyword; Rust: identifier or raw identifier `r#name`, keywords need `r#`, `r#crate/self/super/Self` refused, a lifetime only for a lifetime), `InsideString`, `PossibleFileOperation` (Python `import` module path, Rust `mod name;`), `MacroDefinition` (Rust `macro_rules!` body) |
| Python / Rust server lifecycle | n/a | Restricted Mode: no server process is spawned (`TrustRequired`, recovery Manage Workspace Trust). Lazy start on the first document; `initialize` with the workspace folders; crash → `Restarting` with backoff (1 s, 4 s, 15 s; open documents replayed), more crashes within 3 minutes → `Failed`/`ServerCrashed` (recovery Restart backend); `shutdown` + `exit` on deactivate, then process-tree kill. Missing server for the platform → `Failed`/`ServerNotFound`. Rust without `cargo` (looked up on `PATH`, `CARGO_HOME`, `~/.cargo/bin`; never run) → `Partial`/`CargoNotFound` with **Install Rust** (opens rustup.rs). Server stderr and log messages: debug level, paths redacted |

Reasons the TS/JS route reports instead of an empty result: `ProviderUnavailable` (no TypeScript/JavaScript provider
answered for the document, e.g. the built-in extension is disabled or the file is not in a TS/JS language mode),
`ProviderEmpty`, `ProviderError` (the provider threw; its message is shown), `NotRenameable`, `DocumentChanged` (edited
while the rename was prepared), `ResourceOperation`, `OpaqueEdit`, `NonFileTarget`, `PossibleFileOperation` (a rename
inside a string such as a module path: the public `WorkspaceEdit` API does not list file operations, so it cannot be
previewed), `UnsupportedEncoding`, `MixedLineEndings`, and `ProviderEditChanged` / `RouteChanged` at apply time.

Reasons the Python and Rust routes report: `TrustRequired`, `NotStarted` (Find before the first document), `ServerNotFound`, `ServerStartFailed`, `ServerCrashed`, `CargoNotFound` (Partial), `ServerError`, `ProviderEmpty`, `NotRenameable`, `RenameNotSupported`, `InvalidName`, `InsideString`, `PossibleFileOperation`, `MacroDefinition`, `DocumentChanged`, `ServerViewMismatch`, `ResourceOperation`, `OpaqueEdit`, `NonFileTarget`, `UnsupportedEncoding`, `MixedLineEndings`, `OverlappingEdits`, `EditOutsideDocument`, and `ProviderEditChanged` / `RouteChanged` at apply time.

Not in alpha: automatic fixes, code generation, an own TypeScript worker for TS/JS navigation (TS/JS is delegated to VS Code's built-in features; the web worker answers only React/Next.js/Angular relations), file operations from Python/Rust renames, Python/Rust diagnostics, test navigation and run/debug, additional inspections, C# on platforms other than Windows x64.
